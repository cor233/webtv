# 安全审计修复计划（高危优先）

审计共 37 个报告，归纳为 8 类根因。本次修复 A–G 高危项 + Python TLS 项，H 类低危（硬编码密钥/cleartext/iframe）接受风险并记录到 README。版本 bump 到 **v5.6.0 / versionCode 650**。

---

## 根因 A：本地 HTTP 服务器认证绕过（~15 报告，最高优先级）

**文件**：`app/src/main/java/com/fongmi/android/tv/server/ServerAuth.java`

改动：
1. `protectedPath()` 补充遗漏的播放记录/进度端点：`/api/playback`、`/playback`（否则它们完全无 token 保护，报告 0a2bf/e9961/ae96b/fd160）。
2. 新增 `isSensitivePath(url)` 区分写/敏感操作：`/manage/`、`/file`、`/upload`、`/newFolder`、`/delFolder`、`/delFile`、`/debug/`、`/cache`、`/action`、`/pan/check`、`/api/playback/`、`/playback/`。
3. 改造 `allow()` 逻辑：
   - 敏感写操作 → **始终要求 token**（含 loopback），消除「本机恶意页面/进程无 token 篡改」问题。
   - 读资源端点（`/proxy`、`/webResource`、`/parse`、`/media`、`/m3u8`、`/tvbus`、`/device`）→ loopback 放行，但新增 **Host header 校验**（Host 必须为 `127.0.0.1`/`localhost`/`[::1]` 带端口），防 DNS rebinding（报告 25437 核心攻击路径）。

这一步同时修复报告 25437、352b1、62ecb、75702、932a8、e6d35、d89aa、20464、0a2bf、e9961、ae96b、fd160。管理页 `manage.html` 通过 `withToken()` 生成 URL，始终带 token，不受影响；WebView 内嵌资源走 `/webResource`/`/proxy`，正常带 `127.0.0.1:port` Host，不受影响。

## 根因 B：SSRF（~6 报告）

新增公共工具 `app/src/main/java/com/fongmi/android/tv/utils/UrlSafety.java`：
- `isSafeHttpUrl(url)`：校验 scheme 仅 http/https + DNS 解析后拒绝 anyLocal/loopback/linkLocal/siteLocal 地址（复用 `WebCall.FilteringDns` 的判定逻辑）。

应用到：
1. **WebResourceGateway.java**（报告 5fa8e）：改用 `OkHttp.noRedirect()`，手动循环跟随重定向（上限 5 跳），每一跳都重新 `isSafeHttpUrl` 校验，杜绝重定向绕过。
2. **PlaybackWebhookSender.java**（报告 18409）：`post()` 前对 `config.url` 做 `isSafeHttpUrl` 校验，非法则拒绝投递并记录。
3. **DriveCheckService.java**（报告 9ee30）：`checkUC`/`request` 前校验 URL scheme 仅 http/https 且 host 属于已知网盘域名（drive.uc.cn、pan.uc.cn 等），拒绝任意 URL。
4. **WebHomeExtensionRegistry.java**（报告 63fa8）：`loadRemote` 前对 `sourceUrl` 做 `isSafeHttpUrl` 校验（`file://`/`local://` 仅当来源受信时放行）。
5. **MpvHlsProxy.java**（报告 fa027 + 08616）：`fetch()` 前校验 URL scheme http/https + 非私有地址；`serve()` 入口校验 `?s=` 会话 id 存在且未过期（拒绝伪造/枚举 session，`parseSessionId` 不再回退到当前会话）。

## 根因 C：CORS 反射任意 Origin（~3 报告）

**文件**：`PlaybackProgressApi.java`、`PlaybackRecordApi.java`、`DriveCheck.java`

改动：三处 `cors()` 不再反射任意 Origin + `credentials=true`。改为：仅当 Origin 为本地（`http://127.0.0.1:port` / `http://localhost:port`，复用 `WebResourceGateway.isAllowedOrigin` 逻辑）时回显该 Origin 并允许 credentials；否则不回显 Origin（或返回空）、`Allow-Credentials` 置 false。修复报告 89252、ac50e。

## 根因 D：路径遍历（2 报告）

**文件**：`app/src/leanback/.../VideoActivity.java`、`app/src/mobile/.../VideoActivity.java`（两处 `file()` 相同）

改动：`file()` 前校验：路径规范化后不得包含 `..` 片段，且仅接受媒体扩展名（mp4/mkv/avi/ts/m3u8/flv/mp3/flac 等）；拒绝 `/data/data/`、`/data/user/` 等应用私有目录前缀。修复报告 03d3b、b5901。

## 根因 E：XXE（1 报告）

**文件**：`app/src/main/java/com/fongmi/android/tv/bean/Result.java`

改动：`fromXml()` 入口检测 `<!DOCTYPE` / `<!ENTITY`，命中则直接返回 `empty()`（视频源 XML 无需 DTD/实体），阻断 XXE。修复报告 1db8b。

## 根因 F：DoS / 资源耗尽（3 报告）

1. **SocketHttpStreamServer.java**（报告 e1e05）：`readLine()` 加最大行长（8KB），超限抛异常/断开。
2. **SocketHttpStreamServer.java**（报告 3ceba）：`readBodyInto()` 的 Content-Length 加上限（10MB），超限拒绝。
3. **PlaybackProgressApi.java**（报告 ea022）：`readBody()` 的 `ByteArrayOutputStream(length)` 加上限（10MB），超限抛 `IllegalArgumentException`（现有 `Nano.parse` 的 200MB 上限不覆盖此独立读取路径）。

## 根因 G：信息泄露（~5 报告）

**文件**：`HomeWebBridge.java`
1. **site.info 泄露 header**（报告 5765f、d6ff6）：从 `isUntrustedAllowed()` 白名单移除 `site.info`，使其仅 trusted 可用；untrusted 页面调用返回 Forbidden（`device.info`/`app.history` 已是如此）。
2. **pan.play 无确认 + 任意 scheme**（报告 5b008）：`playPan()` 加 `validatePlayable()`（仅 http/https）并对 untrusted 加 `DependencyTrust.confirmPlay()`（与 `player.playUrl` 一致）。

**cspPage stored XSS**（报告 b118c）：`/manage/csp/page` 属 Manage 写操作，根因 A 修复后 loopback 也需 token，风险已降为「持 token 的管理功能」，本次不再额外处理（README 说明）。

**token in URL**（报告 7593a）：接受风险（二维码/链接访问所必需，代码已注释），README 记录。

## 根因 H：接受风险项

- **硬编码密钥（迅雷签名，报告 4f8b4）**：客户端签名密钥必然在 APK 内，无法真正隐藏。接受风险，README 记录。
- **cleartext 流量（报告 671b0、8cb05）**：直播/媒体源大量 HTTP，无法全局禁；已有 domain-config 对配置源强制 HTTPS。接受风险。
- **WebView iframe 信任边界（报告 a23c2）**：Android `addJavascriptInterface` 无法区分 frame 来源，需深度改造。接受为已知限制，README 记录。
- **Python verify=False（报告 a3c2f）**：修复 `chaquo/src/main/python/app.py` 的 `redirect()`——https 请求恢复 `verify=True`（仅 http 允许无证书），并加 `max_redirects=5` 跳数限制。
